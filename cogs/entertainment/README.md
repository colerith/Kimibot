- Discord 喂食花 **3蛋壳**，与现有身份组商店共用本服务器余额；QQ仍花3粒米。喂食饱腹+12、心情+3、成长+5；摸摸免费，心情+5、成长+1。两种操作各有每人60秒冷却，饱腹≥99时不扣费。
- 同群/服务器大家共养一只奇米，饱食和心情随时间下降，不会死亡，经验每100点升一级。
- 群宠使用彩色Embed面板，显示等级、升级进度条、饱腹、心情、照顾提示及 **60条独立随机日常**。
- 今日运势包含 **60条独立签语**，显示签面、幸运值进度条、幸运色、食物及今日小任务。当天固定，只作娱乐。
- Discord群宠和运势各有每日蛋壳奇遇：每人每服务器每玩法每天首次查看时，等概率奖励或扣除 **0.1～10蛋壳**（0.1为步长）。余额不足仅扣至0，不欠债；面板显示抽取金额、实际加扣和结算后余额。北京时间零点刷新。
- 同日重复查看、切换文字别名、并发请求和重启均不会重复结算。随机结果、余额及流水在蛋壳数据库同一事务持久化；即使后续面板写入失败，重试也只回放结果。QQ不参与蛋壳奇遇。
- 文案位于 `flavor.py`。同一消息重试不重复扣款；蛋壳消费账本记录 `kimi_feed`。蛋壳扣款回执持久化，以防宠物写入失败后重试重复扣款。
- Discord旧饭粒数据保留，不兑换蛋壳；Discord娱乐余额命令及旧文字别名均已移除。QQ与Discord余额不互通。

## 更新与保活

合并对应PR后，QQ项目目录执行：

```bash
git pull --ff-only
docker compose up -d --build bot
docker compose logs --tail=80 bot
```

Kimibot项目目录执行（替换实际PM2进程名）：

```bash
git pull --ff-only
pm2 restart 你的Kimibot进程名
pm2 logs 你的Kimibot进程名 --lines 80
```

Kimibot启动器会自动加载新的 `cogs/entertainment` 文件夹，无需新增进程或安装额外依赖。若斜杠指令暂未刷新，可先使用文字指令，并查看启动同步日志。

QQ默认数据文件 `/data/entertainment.sqlite3` 位于现有Docker数据卷；Discord默认 `data/entertainment.sqlite3` 相对PM2工作目录。可用 `QIMI_FUN_DB` / `KIMI_FUN_DB` 指定路径。不要删除数据卷或改变PM2工作目录，否则可能看起来像余额清空。备份SQLite时建议先停止对应bot。

Discord上线验收：确认娱乐签到命令已移除、喂食扣3蛋壳、冷却及余额不足不扣款；另一成员查看同一只宠物，运势同日不变；重启后状态保留。需要重启机器人完成斜杠命令同步。
