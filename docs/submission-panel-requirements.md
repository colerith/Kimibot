# 投稿功能面板需求文档

## 1. 背景与目标

当前 KimiBot 已引入「蛋壳」作为社区积分体系。本次新增一个独立的投稿功能文件夹与常驻投稿面板，让用户可以用可爱的奇米蛋风格提交 repo、捉虫反馈和安利内容，并与蛋壳奖励联动。

核心目标：

- 新建投稿功能模块文件夹，集中管理投稿面板、投稿表单、投稿消息、奖励结算与管理入口。
- 提供一个公开常驻投稿面板，包含 4 个按钮：📦 我要repo、🐞 我要捉虫、🌟 我要安利、🗂️ 管理投稿。
- 投稿面板通过 `/社区面板 管理` 中的「投稿面板」按钮发送到当前频道。
- 投稿成功后随机奖励合理区间的蛋壳，并写入蛋壳流水。
- 服主可通过按钮回复 repo 与捉虫投稿，回复时通知投稿用户并追加随机蛋壳。
- 安利投稿支持「觉得有用」投票与「盖楼回复」，按有用人数阶梯追加蛋壳奖励。
- 用户可管理自己发出的 repo、捉虫和安利投稿，支持修改内容、删除投稿；删除时从该投稿奖励中扣除一定比例蛋壳。

## 2. 风格要求

投稿面板整体保持「奇米蛋」社区调性：

- 文案可爱、轻松，但功能提示必须清楚。
- 奖励统一称为「蛋壳」。
- 所有蛋壳变动保留 1 位小数。
- 面板交互尽量使用 Discord 原生按钮、Modal、Select 与附件上传能力。
- 投稿类型、安利领域必须使用下拉选单选择，不允许用户手动填写。
- 公开频道只展示必要内容，涉及用户填写过程、个人管理和错误提示的交互应使用仅自己可见的 ephemeral 面板。

附件收集方式参考处罚系统的证据收集流程：

- 用户先通过 Modal 填写投稿文字内容。
- Modal 提交后，系统向用户展示仅自己可见的投稿确认面板。
- 用户可以点击「开始收图」，随后在当前频道发送图片附件。
- Bot 在后台缓存附件文件内容，最多收纳 9 个附件。
- 用户点击「完成投稿」后，Bot 将缓存附件随投稿消息重新发送，并清理用户在当前频道发送的原附件消息。
- 如果用户不需要图片，可直接点击「完成投稿」。
- 收图会话建议 5 分钟后自动过期。

## 3. 功能范围

建议新增模块：

- `submissions`：投稿主面板、repo 投稿、捉虫投稿、安利投稿、投稿管理。
- `points` 或现有蛋壳模块：投稿奖励、追加奖励、扣回奖励、流水记录。

投稿主面板为公开常驻面板，按钮如下：

| 按钮 | 用途 |
| --- | --- |
| 📦 我要repo | 提交想 repo 的对象、标题、类型、内容和图片 |
| 🐞 我要捉虫 | 提交问题反馈、对象、内容和图片 |
| 🌟 我要安利 | 提交安利内容、类型、领域、内容和图片 |
| 🗂️ 管理投稿 | 管理自己发出的 repo、捉虫和安利投稿 |

投稿说明文案应带有轻量 emoji，用于强调入口和流程：

- 📮 想 repo、想捉虫、想安利，都可以投进这里。
- 🥚 奇米蛋会给认真投稿的小饱饱发一点亮晶晶的蛋壳。
- 📎 填完表后可以开启收图，最多收纳 9 张图片。

面板发送入口：

- 管理员使用 `/社区面板 管理` 打开社区面板管理台。
- 点击管理台中的「投稿面板」按钮后，在当前频道发送或更新投稿功能面板。
- 投稿面板与小蛋报到面板同属于社区面板体系，但使用独立模块和独立数据记录。

## 4. 蛋壳奖励规则

### 4.1 基础投稿奖励

每次投稿成功后，系统随机发放合理区间蛋壳。

建议默认区间：

| 投稿类型 | 基础奖励 |
| --- | --- |
| repo | `0.5 - 2.0` 蛋壳 |
| 捉虫 | `0.8 - 2.5` 蛋壳 |
| 安利 | `1.0 - 3.0` 蛋壳 |

要求：

- 奖励区间应可配置。
- 每次奖励写入蛋壳流水，来源标记为对应投稿 ID。
- 投稿失败、表单取消、附件上传失败时不发放奖励。
- 同一用户短时间重复提交可设置冷却时间，避免刷奖励。

### 4.2 服主回复追加奖励

repo 与捉虫投稿被服主通过按钮回复后，系统随机追加蛋壳。

建议默认区间：

- repo 回复追加：`0.3 - 1.5` 蛋壳
- 捉虫回复追加：`0.5 - 2.0` 蛋壳

要求：

- 只有服主或配置的管理身份组可以使用「💌 电波回信」按钮。
- 回复成功后通知投稿用户。
- 追加奖励写入蛋壳流水，并关联投稿 ID 与回复消息 ID。

### 4.3 安利有用人数阶梯奖励

安利消息下展示按钮「觉得有用」。用户点击后计入有用人数，再次点击取消。

建议阶梯奖励：

| 有用人数 | 追加奖励 |
| --- | --- |
| 3 人 | `1.0` 蛋壳 |
| 10 人 | `3.0` 蛋壳 |
| 30 人 | `8.0` 蛋壳 |
| 50 人 | `15.0` 蛋壳 |

要求：

- 每个阶梯只发放一次。
- 取消「觉得有用」后，如果人数低于已发放阶梯，不立即扣回，避免反复震荡。
- 阶梯奖励写入蛋壳流水，并记录触发人数。
- 按钮文案展示当前人数，例如：`觉得有用 12`。

## 5. 我要repo

### 5.1 入口行为

用户点击「我要repo」后，系统展示仅自己可见的投稿面板。

面板需要收集：

- repo 对象，即 repo 的标题。
- repo 类型：通过下拉选单选择 `sfw` / `nsfw`。
- repo 内容。
- 可选上传图片，最多 9 张。
- 图片通过提交后的「开始收图」会话收集，最多 9 张。

### 5.2 发布频道

根据 repo 类型发送到不同频道：

| 类型 | 频道 ID | 展示要求 |
| --- | --- | --- |
| sfw | `1441437806617563156` | 正常展示 |
| nsfw | `1417576370451513495` | 图文都加上剧透效果 |

### 5.3 展示内容

repo 投稿消息应包含：

- 投稿类型：repo
- 投稿标题
- 投稿用户
- repo 类型
- 投稿内容
- 图片附件
- 当前处理状态
- 按钮：💌 电波回信

nsfw 投稿要求：

- 文本内容使用 Discord spoiler 格式包裹。
- 图片附件发送时也应以剧透效果展示。
- 如果平台限制无法直接对重新发送的附件设置剧透，需要下载后以 spoiler 文件名重新上传。

### 5.4 回复与通知

repo 展示出来的内容仅限服主通过按钮回复。

要求：

- 非服主点击「💌 电波回信」时，仅自己可见提示无权限。
- 服主点击「💌 电波回信」后弹出回复 Modal。
- 回复内容追加到投稿展示消息或发送线程回复。
- 系统私信或私密通知投稿用户。
- 回复成功后随机追加蛋壳。

## 6. 我要捉虫

- 捉虫内容。
- 可选上传图片，最多 9 张。
- 图片通过提交后的「开始收图」会话收集，最多 9 张。

捉虫不需要选择 repo 类型。

### 6.2 发布频道

捉虫内容统一发送到频道：

- `1417577014096957554`

### 6.3 展示内容

捉虫投稿消息应包含：

- 投稿类型：捉虫
- 捉虫对象
- 投稿用户
- 捉虫内容
- 图片附件
- 当前处理状态
- 按钮：💌 电波回信

### 6.4 回复与通知

捉虫展示出来的内容仅限服主通过按钮回复。

要求：

- 非服主点击「💌 电波回信」时，仅自己可见提示无权限。
- 服主点击「💌 电波回信」后弹出回复 Modal。
- 回复内容追加到投稿展示消息或发送线程回复。

## 7. 我要安利

### 7.1 入口行为

用户点击「我要安利」后，系统展示仅自己可见的投稿面板。

面板需要收集：

- 安利对象。
- 安利类型：通过下拉选单选择 `sfw` / `nsfw`。
- 安利领域：通过下拉选单选择。
- 安利内容。
- 可选上传图片，最多 9 张。
- 图片通过提交后的「开始收图」会话收集，最多 9 张。

安利领域选项：

- 酒馆好物
- 书籍安利
- 影视安利
- 游戏安利
- 便利生活
- 其他类型

### 7.2 发布频道

安利内容统一发送到频道：

- `1536024803587137536`

### 7.3 展示内容

安利投稿消息应包含：

- 投稿类型：安利
- 安利对象
- 投稿用户
- 安利类型
- 安利领域
- 安利内容
- 图片附件
- 当前有用人数
- 盖楼回复摘要
- 按钮：觉得有用
- 按钮：盖楼回复

nsfw 安利建议与 repo 一致，对图文增加剧透效果。

### 7.4 觉得有用

「觉得有用」按钮行为：

- 用户首次点击后计入有用人数。
- 同一用户再次点击后取消计数。
- 投稿作者点击自己的「觉得有用」不计入人数，并给出仅自己可见提示。
- 按钮状态需要及时更新当前人数。
- 达到阶梯人数时追加蛋壳奖励。

### 7.5 盖楼回复

安利消息下展示按钮「盖楼回复」。

行为要求：

- 用户点击后弹出 Modal。
- 用户可提交公开用户名的评论。
- 评论追加展示到安利面板里，用于发表安利认同、补充体验、注意事项等。
- 每条评论展示评论用户名称、评论内容与时间。
- 同一安利的评论数量过多时，仅在主面板展示最新若干条，并提供查看完整记录的后续扩展空间。

## 8. 管理投稿

### 8.1 入口行为

用户点击「管理投稿」后，系统展示仅自己可见的管理面板。

管理范围：

- 用户自己发出的 repo 投稿。
- 用户自己发出的捉虫投稿。
- 用户自己发出的安利投稿。

repo 与捉虫仍保留服主回复闭环；用户管理入口只负责修改和删除自己的投稿，不代替服主回复。

### 8.2 可管理内容

用户可以按投稿类型修改自己投稿的字段。

repo 可修改：

- repo 对象，即 repo 的标题
- repo 类型：通过下拉选单选择 `sfw` / `nsfw`
- repo 内容
- 图片附件

捉虫可修改：

- 捉虫对象
- 捉虫内容
- 图片附件

安利可修改：

- 安利对象
- 安利类型：通过下拉选单选择 `sfw` / `nsfw`
- 安利领域：通过下拉选单选择
- 安利内容
- 图片附件

用户也可以删除自己的 repo、捉虫和安利投稿。

### 8.3 修改规则

修改投稿时：

- 只能修改自己的投稿。
- 修改后同步更新原频道中的投稿展示消息。
- 修改应保留投稿 ID、原发布时间、当前处理状态与已有服主回复。
- 修改安利时，还应保留有用人数与已有盖楼回复。
- 修改操作不重新发放基础投稿奖励。
- 如果类型从 sfw 改为 nsfw，需要同步增加剧透效果。
- 如果类型从 nsfw 改为 sfw，需要移除后续展示中的剧透效果；历史附件是否重新上传可按实现成本决定。
- 捉虫没有 sfw/nsfw 类型，不展示类型修改入口。

### 8.4 删除规则

用户删除投稿时：

- 只能删除自己的投稿。
- 删除前二次确认。
- 删除后直接删除 Bot 在原频道发布的整条投稿消息。
- 删除后从该投稿的奖励里扣除一定比例蛋壳。

建议默认扣除规则：

- 扣除该投稿已获得总奖励的 `50%`。
- 扣除金额保留 1 位小数。
- 用户余额不足时扣到 `0` 为止，不产生负数余额。
- 扣除操作写入蛋壳流水，来源关联投稿 ID。
- 不扣除其他投稿或其他系统来源的奖励。

## 9. 数据存储需求

建议新增投稿数据表或 JSON 存储结构。

### 9.1 投稿记录

每条投稿至少记录：

- 投稿 ID
- 投稿类型：`repo` / `bug` / `recommendation`
- 投稿用户 ID
- 投稿用户显示名
- 对象或标题
- 类型：`sfw` / `nsfw`，捉虫可为空
- 领域，安利专用
- 内容
- 附件列表
- 发布频道 ID
- 发布消息 ID
- 状态：`open` / `replied` / `edited` / `deleted`
- 基础奖励金额
- 追加奖励金额
- 已触发有用人数阶梯
- 创建时间
- 更新时间

### 9.2 安利互动记录

每条安利至少记录：

- 安利投稿 ID
- 觉得有用用户 ID 列表
- 盖楼回复列表
- 已发放阶梯奖励列表

盖楼回复至少记录：

- 回复 ID
- 回复用户 ID
- 回复用户显示名
- 回复内容
- 回复时间

### 9.3 蛋壳流水

所有蛋壳变动必须写入流水：

- 投稿基础奖励
- 服主回复追加奖励
- 安利有用人数阶梯奖励
- 删除投稿扣回奖励

流水应包含：

- 用户 ID
- 变动金额
- 变动后余额
- 来源类型
- 来源投稿 ID
- 原因描述
- 创建时间

## 10. 权限与风控

### 10.1 权限

- 所有人可点击我要repo、我要捉虫、我要安利。
- 所有人可点击安利下的觉得有用与盖楼回复。
- 只有投稿作者可管理自己的 repo、捉虫和安利投稿。
- 只有服主或配置的管理身份组可回复 repo 与捉虫。

### 10.2 限制

- 每次投稿最多上传 9 张图片。
- 内容长度需要设置合理上限，避免 Discord 消息超长。
- 用户短时间重复投稿应有冷却。
- 同一用户不能给自己的安利计入「觉得有用」。
- 删除投稿需要二次确认。

## 11. 交互验收标准

- 公开投稿面板可以正常展示 4 个按钮。
- 管理员可以通过 `/社区面板 管理` 中的「投稿面板」按钮发送或更新公开投稿面板。
- 点击我要repo、我要捉虫、我要安利后，只向点击用户展示私密投稿流程。
- 投稿表单提交后可以开启附件收集，会话最多收纳 9 个附件，并在完成投稿后清理原附件消息。
- repo 的 sfw 内容发送到 `1441437806617563156`。
- repo 的 nsfw 内容发送到 `1417576370451513495`，且图文使用剧透效果。
- 捉虫内容统一发送到 `1417577014096957554`。
- 安利内容统一发送到 `1536024803587137536`。
- 投稿成功后随机发放蛋壳，并写入流水。
- repo 与捉虫只能由服主通过按钮回复，回复后通知投稿用户并追加蛋壳。
- 安利下的觉得有用按钮可以统计人数，再次点击可以取消。
- 安利达到阶梯人数后会追加蛋壳奖励，且每档只发放一次。
- 安利下的盖楼回复可以追加公开用户名评论。
- 用户可以通过管理投稿修改自己的 repo、捉虫和安利投稿。
- 用户删除自己的 repo、捉虫或安利投稿后，会按比例扣除该投稿奖励。

## 12. 后续扩展

- 管理员审核投稿后再公开发布。
- 管理员配置奖励区间、阶梯奖励与频道 ID。
- repo、捉虫也支持用户查看历史记录。
- 安利详情页展示完整盖楼回复。
- 投稿面板支持定时刷新统计数据。
